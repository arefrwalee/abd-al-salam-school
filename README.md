# نظام إدارة مدرسة عبد السلام الذكي
**Abd Al-Salam Smart School Management System — الإصدار 3.1**

🔗 **العرض المباشر (Live Demo):** https://arefrwalee.github.io/abd-al-salam-school/
> يعمل العرض المباشر في «وضع العرض» ببيانات تجريبية في الذاكرة فقط، ولا يُحفظ فيه شيء. الحسابات التجريبية تظهر في صفحة الدخول.

واجهة مكتوبة بـ HTML + CSS + JavaScript دون أي إطار عمل، مع خادم Node.js لا يحتاج أي حزمة خارجية. تُحفظ البيانات على خادم المدرسة في قاعدة SQLite مشفّرة، لا في LocalStorage.

---

## 1. التشغيل السريع

**المتطلبات:** Node.js بالإصدار 22.13 أو أحدث، ويُنزَّل من nodejs.org. لا حاجة إلى `npm install`.

```bash
# من داخل مجلد المشروع
node server/server.js
```
- على ويندوز: انقر نقرًا مزدوجًا على `start-windows.bat`
- على لينكس أو ماك: نفّذ `./start.sh`

بعدها افتح المتصفح على **http://localhost:8080**. في أول تشغيل تظهر شاشة «الإعداد الأول»، وفيها تحدد:
- اسم المدرسة واسم المدير.
- اسم دخول المدير وكلمة مروره.
- إن كنت تريد تحميل بيانات تجريبية: 120 طالبًا، و10 مدرسين، وحضور ودرجات ورسوم.

عند تحميل البيانات التجريبية تعمل هذه الحسابات للتجربة:

| الدور | اسم الدخول | كلمة المرور |
|---|---|---|
| مدرس | `teacher1` … `teacher10` | `Teacher@123` |
| طالب | `student1` … `student120` | `Student@123` |
| ولي أمر | `parent1` … | `Parent@123` |

> الحسابات الجديدة التي تُنشئها الإدارة تحصل على كلمة مرور عشوائية مؤقتة تظهر مرة واحدة، ويُطلب من صاحبها تغييرها عند أول دخول.

## 2. أين تُحفظ البيانات؟ ولماذا هي آمنة؟

| الطبقة | ما يحدث |
|---|---|
| **الخادم** | كل سجل يُشفَّر بخوارزمية **AES-256-GCM** قبل حفظه في `data/school.db`، فسرقة ملف القاعدة وحده لا تكشف أي اسم أو درجة. |
| **مفتاح التشفير** | يوجد في `data/master.key` بصلاحية 600، أو يُمرَّر عبر المتغير `SCHOOL_MASTER_KEY`. **احفظ نسخة منه خارج الجهاز، فبدونه لا يمكن قراءة البيانات أبدًا.** |
| **كلمات المرور** | تُخزَّن بخوارزمية **scrypt** مع ملح عشوائي لكل مستخدم، ولا تصل إلى المتصفح إطلاقًا. |
| **الجلسات** | محفوظة في كوكي `HttpOnly` و`SameSite=Strict` لا تستطيع JavaScript قراءته، ويحفظ الخادم بصمتها (hash) فقط. |
| **الصلاحيات** | يتحقق الخادم من **كل** عملية قراءة وكتابة: المدرس يرى فصوله فقط، وولي الأمر يرى أبناءه فقط، ولا يمكن تجاوز ذلك حتى بتعديل الواجهة. |
| **سجل النشاط** | يكتبه الخادم بنفسه لكل إنشاء أو تعديل أو حذف أو دخول، ولا يمكن تزويره من الواجهة. |
| **الحماية من الهجمات** | قفل الحساب بعد 5 محاولات خاطئة، وحدّ لعدد محاولات الدخول من كل جهاز، وحماية CSRF، ورؤوس أمان (CSP و X-Frame-Options وغيرها). |
| **النسخ الاحتياطي** | نسخة تلقائية مشفّرة كل 24 ساعة في `data/backups` تُحفظ منها آخر 14 نسخة، مع نسخة يدوية من الإعدادات مشفّرة بكلمة سر تختارها. |

### العمل دون اتصال
عند انقطاع الشبكة يبقى التطبيق يعمل:
- **نسخة مشفّرة على الجهاز:** تُحفظ نسخة من بيانات المستخدم في IndexedDB مشفّرة بـ AES-256، ومفتاحها مغلّف بكلمة مرور المستخدم عبر PBKDF2 بـ 210,000 تكرار.
- **الدخول دون اتصال:** يدخل المستخدم بكلمة مروره نفسها، ويُسجّل الحضور ويُدخل الدرجات كالمعتاد.
- **المزامنة:** تُرسل التعديلات تلقائيًا عند عودة الاتصال، ويتحقق الخادم منها كأي تعديل آخر.
- **الحذف من الجهاز:** يمكن حذف النسخة من الجهاز في أي وقت من «ملفي الشخصي».

> ⚠️ المتصفحات لا تسمح بالتشفير دون اتصال إلا عبر **HTTPS** أو **localhost**. على جهاز الخادم نفسه يعمل ذلك مباشرة. للأجهزة الأخرى في الشبكة فعّل HTTPS كما في القسم 3؛ وبدونه يعمل النظام عبر الشبكة بشكل طبيعي لكن دون نسخة على الجهاز.

## 3. الاستخدام من أجهزة أخرى في المدرسة (الشبكة المحلية)

1. شغّل الخادم على جهاز ثابت في المدرسة. يستمع الخادم افتراضيًا على كل الواجهات (`0.0.0.0:8080`).
2. اعرف عنوان الجهاز في الشبكة، مثل `192.168.1.20`.
3. افتح من الأجهزة الأخرى: `http://192.168.1.20:8080`

**تفعيل HTTPS (موصى به):**
```bash
# مرة واحدة: أداة mkcert تنشئ شهادة موثوقة محليًا
mkcert -install
mkcert 192.168.1.20 localhost
# التشغيل مع HTTPS
SCHOOL_TLS_CERT=./192.168.1.20+1.pem SCHOOL_TLS_KEY=./192.168.1.20+1-key.pem node server/server.js
```
بعد ذلك ثبّت شهادة mkcert الجذرية على الأجهزة الأخرى، وافتح `https://192.168.1.20:8080`.

### متغيرات البيئة
| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `8080` | المنفذ |
| `HOST` | `0.0.0.0` | استخدم `127.0.0.1` لمنع الوصول من الشبكة |
| `SCHOOL_DATA_DIR` | `./data` | مجلد القاعدة والمفتاح والنسخ |
| `SCHOOL_MASTER_KEY` | — | مفتاح التشفير بصيغة base64 (32 بايت) بدل ملف `master.key` |
| `SCHOOL_TLS_CERT` / `SCHOOL_TLS_KEY` | — | تفعيل HTTPS |

## 4. هيكلية المشروع

```
abd-al-salam-school/
├── server/                    ← الخادم (Node.js فقط، بدون حزم)
│   ├── server.js              التوجيه، واجهة API، الملفات الثابتة، التحديث الفوري (SSE)
│   ├── db.js                  SQLite + تشفير AES-256-GCM لكل سجل + الجلسات + النسخ
│   ├── auth.js                scrypt، كلمات المرور المؤقتة، الكوكي
│   ├── policy.js              الصلاحيات: ما يُقرأ وما يُكتب لكل دور
│   └── config.js              الإعدادات
├── public/                    ← الواجهة (HTML/CSS/JS بدون أطر عمل)
│   ├── index.html  sw.js  manifest.webmanifest  icon.svg
│   ├── css/                   tokens · base · layout · components · pages · sync · print · responsive
│   └── js/
│       ├── core/              utils · repo (المستودع والإعدادات) · auth · permissions
│       ├── data/              sync (الوصلة مع الخادم) · vault (الخزنة المشفّرة) · seed (بيانات تجريبية)
│       ├── services/          domain (قواعد العمل، الحسابات، الإنذار المبكر، الرؤى)
│       ├── smart/             assistant (المساعد الذكي بالعربية)
│       ├── ui/                components (الجداول، النوافذ، الرسوم، QR)
│       ├── pages/             shell · academic · evaluation · admin
│       └── main.js            الإقلاع واختيار الوضع
├── data/                      ← يُنشأ تلقائيًا: school.db · master.key · backups/
├── start-windows.bat  start.sh  package.json  README.md
```

### أوضاع التشغيل الثلاثة
| الوضع | متى | أين تُحفظ البيانات |
|---|---|---|
| **الخادم** | عند الفتح من `http(s)://…` والخادم يعمل | على الخادم (مشفّرة)، مع نسخة مشفّرة على الجهاز |
| **دون اتصال** | الخادم غير متاح وتوجد نسخة على الجهاز | الخزنة المشفّرة، ثم تُزامَن تلقائيًا |
| **العرض** | فتح `index.html` مباشرة أو المعاينة | الذاكرة فقط، وتُحذف عند إغلاق الصفحة |

## 5. واجهة API (للتطوير اللاحق)

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/public` | معلومات عامة (هل يحتاج إعدادًا؟) |
| POST | `/api/setup` | الإعداد الأول (مرة واحدة) |
| POST | `/api/login` · `/api/logout` | الدخول والخروج |
| GET | `/api/me` | المستخدم الحالي |
| GET | `/api/sync?since=N` | البيانات المسموحة للمستخدم (كاملة أو التغييرات فقط) |
| POST | `/api/ops` | تعديلات (كل عملية يتحقق منها الخادم) |
| GET | `/api/events` | تحديثات فورية (SSE) |
| PUT | `/api/settings` | الإعدادات (المدير) |
| POST | `/api/users` · `/api/users/password` · `/api/password` | الحسابات وكلمات المرور |
| POST | `/api/backup` · `/api/restore` · `/api/reset` | النسخ الاحتياطي والاستعادة (المدير) |
| GET | `/api/verify?code=` | التحقق العام من الشهادات |

كل الطلبات التي تغيّر البيانات تتطلب الترويسة `X-Requested-With: abd-al-salam`، وهي جزء من حماية CSRF.

## 6. ملاحظات للمرحلة القادمة
- **استبدال SQLite:** طبقة التخزين معزولة في `server/db.js`، ويمكن استبدالها بـ PostgreSQL مع الإبقاء على نفس الدوال (`put`، `get`، `live`، `replaceAll`) دون لمس الواجهة.
- **الذكاء التوليدي:** المساعد الحالي يعمل محليًا. لربطه بنموذج لغوي أضف مسارًا في الخادم يستدعي النموذج بأدوات تعيد البيانات بعد تطبيق `policy.js`، فلا يرى النموذج إلا ما يحق للمستخدم.
- **قبل الاستخدام الفعلي:**
  - غيّر كل كلمات المرور التجريبية، أو أعد الإعداد دون بيانات تجريبية.
  - فعّل HTTPS.
  - احفظ `master.key` في مكان آمن.
  - جرّب الاستعادة من نسخة احتياطية مرة واحدة على الأقل.
